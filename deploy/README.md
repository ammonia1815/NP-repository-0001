# 외부 노출 설정 (Phase 3) - 완료

## 최종 구성
- 공유기(`192.168.35.1`, HFR H734G): 이 공유기는 **외부 80/443 포트를 열면 내부 웹 브라우징 전체를 가로채 마비시키는 버그가 있어** 80/443은 사용하지 않음
- 포트포워딩: 외부 **25575** → 내부 `192.168.35.193:443` (TCP)
- 고정 DHCP: `192.168.35.193` ↔ MAC `30:c5:99:56:92:bf`
- DuckDNS 도메인: `ainpc.duckdns.org` (5분마다 자동 IP 갱신, "엔피 DuckDNS 갱신" 예약 작업)
- 인증서: Let's Encrypt, **DNS-01 챌린지**로 발급 (포트 개방이 전혀 필요 없는 방식 - 위 80/443 문제 때문에 HTTP-01/TLS-ALPN-01 대신 이 방식 사용)
  - Caddy에 `caddy add-package github.com/caddy-dns/duckdns`로 DuckDNS DNS 플러그인 추가
  - `deploy\Caddyfile`에 DuckDNS 토큰으로 `tls { dns duckdns <토큰> }` 설정
- Windows 방화벽: Caddy 실행 파일에 대해 인바운드 443 허용 (80은 불필요 - 외부에서 25575로만 들어오고, 내부적으로 25575가 아닌 443으로 라우팅되므로 로컬 443 리스닝만 필요)

## 자동 시작
Windows 서비스(LocalSystem 계정)로 등록을 시도했으나 원인 불명으로 계속 즉시 종료되어(1.5초 내 크래시 반복), **로그인 시 자동 실행되는 예약 작업** 방식으로 대체했습니다.
- 예약 작업 이름: "엔피 Caddy 자동시작" (트리거: 이 계정 로그온 시, 검은 창 없이 조용히 실행 - `deploy\start-caddy.vbs` 경유)
- 수동으로 다시 켜야 할 때: `caddy run --config "C:\AI NPC 0901\deploy\Caddyfile"` 또는 작업 스케줄러에서 "엔피 Caddy 자동시작" 실행
- 인증서/상태 저장 위치: `deploy\caddy-data\` (특정 사용자 계정에 종속되지 않도록 프로젝트 폴더 안에 고정)

## 확인된 사항 (curl 및 실제 폰으로 직접 검증 완료)
- `https://ainpc.duckdns.org:25575/health` → `{"status":"ok"}`
- 인증서 정상 신뢰됨 (curl이 `-k` 없이도 통과, 폰 브라우저 자물쇠 아이콘도 정상)
- `POST /api/message`로 실제 메시지 전송 → Gemini 응답 + TTS 음성까지 정상 수신
- **실제 폰으로 같은 집 와이파이 + 모바일 데이터(와이파이 끔) 양쪽 모두 정상 접속 확인 완료** - 진짜 야외 접속까지 검증됨

## 안드로이드 앱 설정
설정 화면의 "서버 주소"에 **포트 번호까지 포함해서** 입력해야 합니다:
```
https://ainpc.duckdns.org:25575
```
토큰은 데스크톱 앱 설정 창에서 복사한 값 그대로 사용.

## 참고: 이 공유기에서 배운 것
- **80/443 포트포워딩은 절대 켜지 마세요.** 외부 요청뿐 아니라 이 PC를 포함한 내부 기기의 모든 웹 트래픽까지 이 규칙으로 가로채는 것으로 추정됩니다 (실제로 두 번 재현됨).
- 마인크래프트 등에 쓰던 것처럼 80/443이 아닌 포트는 정상 동작합니다.
